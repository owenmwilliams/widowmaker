# iOS surface brief — Nexus Moves design language

Read `design/briefs/COMMON.md` first. Branch: `claude/ios-design` from latest
`origin/main`. Scope: `MoveTrack-iOS/` only. Reference kit:
`design/ui_kits/mobile_app/index.html` (this IS your product surface). No
iOS build in CI: brace/logic-check rigorously, state verification honestly in
the PR; the owner validates in Xcode before any TestFlight build.

## 1. Theme layer (first PR-able commit)
Rebuild `Theme` in `MoveTrack-iOS/widowmaker/MoveTrack/` as the generated
layer over `design/tokens/tokens.json`:
- **Semantic Colors** (dark default + light variants via dynamic
  UIColor/Color): `accent` #4F5BF0, `surface`, `surfaceCard`, `textPrimary`,
  `textSecondary`, `border`, `bubbleSelf`, semantic success/warn/danger,
  `beacon` #F98D5B, navy ink ramp. Transcribe names 1:1 from tokens.json so
  future regeneration is mechanical.
- **The app is DARK-FIRST**: dark is the default appearance; light must also
  be correct (test both). This flips today's light look — expected.
- **Shimmer**: `LinearGradient` at 115°, stops #3B6FE0 → #2F8FE0 → #34C8E0.
  Used ONLY: assistant avatar, readiness progress fill, the single hero CTA
  ("Share inventory"). Sweep animation only where the kit shows it, disabled
  under Reduce Motion.
- **Spacing**: 4pt grid constants. **Radii**: buttons/inputs 14, cards 18,
  chat bubbles/panels 22, sheets 28, pills capsule. **Tap targets ≥44pt.**
- **Type**: system SF for all UI mapped to Dynamic Type styles (body ≥15,
  chat body 17, titles 22+ — never hard-lock sizes); JetBrains Mono (bundle
  OFL font) for data readouts (weights/volumes) and uppercase eyebrows.
  Bricolage Grotesque is display-only — SKIP bundling it in v1; use system
  bold where the kit shows display type, flag any screen that truly needs it.

## 2. Screen-by-screen application (kit is the layout truth)
- `NexusChatView`: assistant bubbles = `surfaceCard` (radius 22), user
  bubbles = solid `accent`; quick-start chips → SuggestionButton block
  variant (full-width); upload progress row → ProgressBar shimmer fill;
  error bar → Banner (cream/amber "honest nudge" style); scan-review pills →
  StatusPill contract; composer → Input `composer` variant + 44pt
  IconButtons.
- `ReadinessSheet`: Sheet (radius 28), ChecklistItem for Next Steps rows
  (keep the tap-to-send behavior EXACTLY), shimmer ProgressBar, warning →
  Banner. Share CTA is the screen's one shimmer button.
- `ReviewItemsSheet` / `DuplicateReviewSheet`: Sheet + ItemCard/ChecklistItem
  contracts; commit button solid `accent` (NOT shimmer).
- `LoginView` / `LaunchSplashView`: logo assets from `design/assets/`
  (mark on dark), dark surface, type scale; keep auth/splash behavior
  untouched.
- Assistant avatar: the sparkles-on-shimmer mark per
  `design/components/chat/AssistantAvatar.*` — the ONLY filled brand mark.
- Icons: keep SF Symbols in v1, prefer line-weight variants that read like
  Lucide (2px line, rounded); no emoji anywhere in UI (audit existing
  strings: the optimistic-bubble "📷/🎥" prefixes and attachment chip labels
  must become icon+text).
- App icon: `design/assets/app-icon.svg` — needs 1024px PNG export into the
  asset catalog. If you cannot rasterize in your environment, leave the
  catalog untouched and flag it as an owner action in the PR.
